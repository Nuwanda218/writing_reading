# 存储层次与缓存：为什么电脑要"分层存东西"

> 变更日志：
> - v1.0 | 2026-10-08 15:35:01 | 初版：局部性原理、缓存工作机制（块/映射/替换/写策略）含手算、内存墙与 HBM

先问你一个反直觉的问题：**你的电脑有 16 GB 内存，为什么 CPU 旁边还要塞几 MB 的缓存？** 16 GB 明明装得下所有数据，缓存那几 MB 不是多此一举吗？

答案有点意外：**因为内存太慢了。** 慢到什么程度？CPU 从寄存器取一个数大约 1 纳秒，从内存取一个数要 100 纳秒——**差 100 倍。** 如果 CPU 每次都直接去内存拿数据，它 99% 的时间都在干等。

这篇讲的就是人类怎么解决这个"干等"问题。它叫**存储层次（Memory Hierarchy）**，而其中最精彩的一环是**缓存（Cache）**。

## 一、它是什么：一座"速度金字塔"

先看事实。计算机的存储从来不是一块，而是一座金字塔，从塔尖到塔底：

| 层次 | 速度（取一次） | 容量 | 谁在用 |
|---|---|---|---|
| 寄存器（Register） | < 1 ns | 几百字节~几 KB | CPU 正在算的数 |
| L1 缓存 | ~1 ns | 几十 KB | 每个核心私有 |
| L2 缓存 | ~4 ns | 几百 KB~几 MB | 每个核心私有 |
| L3 缓存 | ~15 ns | 几 MB~几十 MB | 所有核心共享 |
| 内存（DRAM） | ~100 ns | 几 GB~几百 GB | 整个系统 |
| 固态硬盘（SSD） | ~100 μs | 几百 GB~几 TB | 长期存储 |
| 机械硬盘（HDD） | ~10 ms | TB 级 | 冷数据仓库 |

规律很清楚：**越往上越快、越小、越贵；越往下越慢、越大、越便宜。** 塔尖到内存差 100 倍，内存到机械硬盘差 10 万倍。

比喻一下：**寄存器是你手边的笔，L1/L2 是书桌，L3 是书架，内存是书房，SSD 是家里的书柜，硬盘是图书馆。** 你写东西时只碰手边的笔；要查资料，先看书桌有没有，没有去书架，再没有才跑一趟图书馆。**没人会为了查一个词，每次都跑图书馆。**

**这座金字塔能成立，全靠一个经验规律：局部性原理（Principle of Locality）。** 它说：程序访问数据不是随机的，而是"扎堆"的——

- **时间局部性（Temporal Locality）**：刚用过的数据，很可能马上还要用。比如循环里的计数器 `i`。
- **空间局部性（Spatial Locality）**：刚用过的数据，它旁边的数据很可能也要用。比如遍历数组 `a[0], a[1], a[2]...`。

**局部性就是这座金字塔的地基。** 如果程序真的随机乱访问，缓存毫无意义——每次都得去最慢那层拿。正因为访问"扎堆"，我们才能把最常用的那一小撮数据放在塔尖，让 90% 以上的访问都命中在快的那几层。

## 二、缓存怎么工作（机制核心）

现在钻进最精彩的一环：缓存。它夹在 CPU 和内存之间，是一块小而快的存储器。**它的全部工作，就是替 CPU 挡住那些"要跑一趟内存"的访问。**

### 2.1 一次搬一整块：缓存行

第一个关键设计：**缓存不是按"一个字节"搬数据，而是按"一整块"搬。** 这一块叫**缓存行（Cache Line）**，今天通常是 64 字节。

为什么？因为空间局部性。你要读 `a[0]`，那 `a[1]`、`a[2]` 大概率马上也要读——**与其来回跑，不如一次把 64 字节全搬回来。** 这就像去超市买鸡蛋：不会一次只买一个，而是买一整盒。

### 2.2 命中与缺失

CPU 要数据时，先问缓存："你有吗？"

- **命中（Hit）**：有，直接拿走，快。
- **缺失（Miss）**：没有，得去内存搬，慢——而且搬的时候 CPU 只能干等。

缺失分三类（业内叫 3C）：

- **强制缺失（Compulsory Miss）**：这块数据第一次被访问，缓存里当然没有。**躲不掉。**
- **容量缺失（Capacity Miss）**：缓存太小，装不下程序的工作集，旧数据被挤出去，回头又要用。**加缓存能缓解。**
- **冲突缺失（Conflict Miss）**：缓存明明还有空位，但数据被"规则"限制只能放某个固定位置，位置被占了。**改规则能缓解——这就引出了映射方式。**

### 2.3 三种映射：数据该放哪一行？

缓存内部被切成若干个"行"（槽位）。一个内存块搬进来，能放哪儿？三种规矩：

- **直接映射（Direct Mapped）**：每个内存块只能放**唯一固定**的一行。规则最简单（通常按地址取模），查得最快，但**容易冲突**——两个块抢同一个位置，就会互相挤。
- **全相联（Fully Associative）**：任意块可以放**任意**一行。最灵活、冲突最少，但硬件要同时比较所有行，**电路贵、速度慢**。
- **组相联（Set Associative）**：折中方案。把缓存分成若干组，每组有 N 行（叫 N 路组相联），块先按规则定到某一组，组内可以随便放。**今天的 CPU 几乎都用它**，比如 8 路组相联。

地址因此被切成三段：**标记（Tag）+ 组索引（Index）+ 块内偏移（Offset）**。组索引决定"去哪个组"，标记用来确认"是不是我要的那块"，偏移定位"块内第几个字节"。

### 2.4 替换与写：满了挤谁？改了怎么办？

- **替换策略**：组满了要挤走一个，挤谁？最常用的是 **LRU（Least Recently Used，最近最少使用）**——挤掉最久没被碰过的那个。依据还是时间局部性：**刚用过的，接下来更可能用。**
- **写策略**：CPU 改了数据，缓存和内存怎么同步？**写回（Write-back）**是只改缓存、等这块被挤出去时再写回内存（省带宽，主流做法）；**写直达（Write-through）**是每次改都同时写内存（简单，但费带宽）。

### 2.5 手算：同样 64 次访问，命中率能差多少？

光说原理不够，我们算一笔账。设缓存能放 **4 个块**，每块 **4 个字**；有一个 8×8 的数组 `a[8][8]`，按行优先存储（C 语言就是这样：`a[i][j]` 的地址 = i×8 + j）。

**第一种：按行遍历**（`for i: for j: sum += a[i][j]`）。访问顺序是 a[0][0..7]、a[1][0..7]……

- a[0][0] 缺失，把整块 a[0][0..3] 搬进来 → 之后 a[0][1]、a[0][2]、a[0][3] 全命中；
- a[0][4] 缺失，搬入 a[0][4..7] → 后三个命中；
- 以此类推，**每 4 次访问缺 1 次，命中率 75%。**

**第二种：按列遍历**（`for j: for i: sum += a[i][j]`）。访问顺序是 a[0][0]、a[1][0]、a[2][0]……

- a[0][0] 缺失，搬入 a[0][0..3]；但下一个访问的是 a[1][0]，地址隔了 8 个字，**落在另一个块**；
- 8 行轮一遍要 8 个块，缓存只有 4 个位置——**每次新访问都把上一块挤掉**；
- 结果：**几乎每次访问都缺失，命中率接近 0%。**

**同样 64 次加法，一个命中率 75%，一个接近 0%。** 这就是"缓存友好"四个字的全部含义——**数据没变、算法没变，只是访问顺序变了，性能差好几倍。** 你以后写循环时把最内层留给连续访问的那一维，就是在照顾这座金字塔。

## 三、它怎么来的：内存墙逼出缓存

**核心矛盾：CPU 和内存的进步速度不一样。**

摩尔定律让 CPU 每两年翻一番，但内存（DRAM）的速度提升慢得多——**CPU 越跑越快，内存越落越远。** 这个缺口在 1994 年被正式命名：**内存墙（Memory Wall）**。

墙逼出了缓存。1968 年，IBM System/360 Model 85 第一次把缓存做进商用计算机；此后缓存从一层变两层（L1/L2）、再变三层（L3），容量从几 KB 涨到几十 MB。**这不是设计者的偏好，是"CPU 等不起"逼出来的必然。**

2006 年之后，CPU 频率撞上发热墙，人类转向多核——**这一转，缓存变得更关键**：多个核心抢内存，谁的数据在缓存里，谁就跑得快。而行话里那句"内存墙比频率墙更难翻"，说的就是这件事。

## 四、它为什么重要：算一笔账

**第一笔账：一次缺失有多贵。** 寄存器 ~1 ns，内存 ~100 ns。假设缓存命中要 1 ns、缺失要 100 ns，那么平均访问时间 = 命中率 × 1 + 缺失率 × 100：

- 命中率 **95%**：0.95×1 + 0.05×100 = **5.95 ns**
- 命中率 **99%**：0.99×1 + 0.01×100 = **1.99 ns**

**命中率只提高 4 个百分点，平均速度快了 3 倍。** 这就是为什么缓存设计是 CPU 性能的头号战场——**它不需要让任何零件变快，只需要让"等"的次数变少。**

**第二笔账：AI 的瓶颈也在这座金字塔上。** 还记得《推理工程》里那个现象吗——大模型解码段"卡在内存读取上"，KV 缓存是"显存黑洞"，量化是为了"读得动"。**现在你能看到它的硬件根源了：** 那些问题全是存储墙的变体——**算力早就过剩，数据搬不过来。**

GPU 内部同样是一座金字塔：寄存器 → 共享内存（Shared Memory）→ L2 → 显存（HBM）。几千个核心要同时干活，**喂饱它们的难度，比造出它们大得多。** 这就是为什么 AI 芯片的竞争，很大一部分是"内存带宽"的竞争。

## 五、现在怎么样 + 将去哪里

- **HBM（High Bandwidth Memory，高带宽内存）**：把内存芯片一层层 3D 堆叠起来，用更宽的总线连到 GPU 旁边——**今天所有顶级 AI 芯片的标配**，也是"显存带宽"这个热搜词的实体。
- **CXL（Compute Express Link）**：一种让 CPU、GPU、内存之间高速共享的互联协议，目标是让"内存"不再被绑死在一台机器上。
- **存算一体（Processing-in-Memory，简称 PIM）**：釜底抽薪的一招——**既然瓶颈是"搬"，那就不搬了，直接在存储里算。** 这正是《计算机硬件》第五节"第三招"的展开。
- **近存计算、3D 堆叠、光互联**：都在朝同一个方向使劲——**把数据搬运的距离和代价压到最低。**

**可见，存储层次的下一幕，从"把常用的数据放近一点"，走向"让数据根本不用搬家"。**

## 六、小结 + 下一片叶子

小结时刻。

**存储层次是硬件层里最"反直觉"的一课：它不靠把零件做快，而靠"把常用的放近、把不常用的放远"，用局部性原理骗过物理极限。** 缓存是这套骗术的核心——块、命中、映射、替换、写策略，五个零件咬合起来，让 90% 以上的访问都落在快的那几层。

**下次你写代码时把最内层循环留给连续内存，或者看到"某模型显存带宽吃紧"的新闻，你就知道：那都是这座金字塔在收过路费。**
