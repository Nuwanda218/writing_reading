先给你一个安心的承诺：大语言模型（LLM，Large Language Model）不是某个天才一夜之间的发明。它是一条横跨七十年的演化链，每一环都在解决上一环留下的死穴。你现在已经懂"神经网络怎么学会一件事"，正好从这条链的第一环出发，一路走到 ChatGPT——你会看到，它每一步都踩着你认识的那几块砖。

这篇文章是整条链的树干：每步讲清"当时的技术是什么、靠什么运转、为什么被取代"。文末会指出哪些细节值得下钻（Transformer 的完整机制、GPT 怎么生成、对齐怎么做），那是下一片叶子的树干。

## 第一步：算术时代（1950s—1990s）：语言模型 = 数数

一切从一个问题开始：**机器怎么知道"哪句话更像人话"？** 回答这个问题的东西，叫**语言模型（Language Model，简称 LM）**。它的任务，就是算"这句话出现的概率有多大"——概率高 = 通顺，概率低 = 不像人话。语言模型最原始的用途，是帮语音识别和机器翻译在几个候选句子里挑"最像人话的那句"。

最早的思路朴素得令人发指：**数数。** 统计海量文本里"哪些词总挨着哪些词出现"，然后按频率猜下一个词——这个办法叫 **n-gram（n 元语法）**。它只靠"数相邻词的组合出现了几次"来估计概率。

具体怎么数？按"几个词一组"分粗细。看一个迷你语料，假设只有三句话："我喜欢猫""我喜欢狗""你养猫"。如果只数单个词（这叫 **unigram**，一元语法），"猫"出现 2 次、总词数 8 → P(猫) = 2/8 = 0.25。如果数两个相邻词的组合（这叫 **bigram**，二元语法）："我"后面跟"喜欢"出现了 2 次，而"我"一共出现 2 次 → P(喜欢|我) = 2/2 = 1。还可以数三个词的组合（**trigram**，三元语法）。**n 越大，看得越远，越接近"人话"；但代价是"n 个词的组合"越稀罕，越难数到。**

它有两个死穴。**一是"数据稀疏"**：语言太自由了，"猫在沙发上打滚"这种组合，可能整个语料库都没出现过一次，频率记成 0——但人都会说。稀疏的根源在于组合是爆炸的：光"猫 在 沙发 上 打 滚"这一个 6 词组合，就要这 6 个词恰好连在一起出现过一次才数得到，而真实语料里这种长组合几乎不会重复第二次。所以 n 一旦大于 3，"没见过的组合"是常态——频率全记成 0。补救的办法叫**平滑（Smoothing）**：给没出现过的组合一个很小的概率（比如千分之一），而不是干脆记 0，别让模型一票否决。**二是"看得太近"**：n-gram 就算 n 取到 5，也只看得到 5 个词内的关系，记不住长距离——"虽然……但是……"中间隔了 200 个字，它就断了。这个时代的语言模型，本质上是一台"计数器"。

## 第二步：神经网络进场（2003，NNLM）

2003 年，本吉奥（Bengio，后来的深度学习三巨头之一）提出 **NNLM（Neural Network Language Model，神经网络语言模型）**——第一次让神经网络来算"下一个词的概率"。

它怎么运作？用个小例子。假设词典只有 5 个词（我、喜欢、猫、狗、你），我们只看前面 2 个词，要预测第 3 个。NNLM 做两件事：**第一**，把前面每个词查一张"词表"变成数字向量（比如"我"变成 [0.2, −0.5, 0.8] 这种坐标，每个词有自己固定的那行数字）；**第二**，把这两个向量拼起来喂给一个神经网络，网络算出一份"下一个词的概率"——词典里每个词各得一个概率，最高的就是它的猜测。

**它和 n-gram 的本质区别，是"计数"和"学习"的区别。** n-gram 是查表：数"喜欢猫"出现过几次，出现过就记高、没出现过就记 0，**词与词之间没有任何联系**。NNLM 是学习：它学到的是一套"把上下文变成概率"的函数，而词在数字空间里的位置是相通的——**"猫"和"狗"因为总出现在相似句子里，向量挨得近**。于是即便它从没见过"我喜欢猫"，但只要见过"我喜欢狗"，它就能推断"猫"在这里也该有不低的概率。这种"相似的词互相借力"的能力叫**泛化（Generalization）**——这正是它比 n-gram 强、能缓解数据稀疏的根本原因。

而这件事有个当时没被重视、后来却无比重要的**副产品**：前面说的"查词表变成向量"——那张表里的每一行，就是**词向量（Word Vector）**。本吉奥本意只是让网络能算数，结果发现这些向量自己学会了词的"意思"。它成了后面第三步的地基。换句话说：**词嵌入的种子，早在 2003 年就无意间种下了。**

NNLM 当时没普及（2003 年训练它要跑几周，数据也小），但它证明了"用网络学语言"这条路走得通——为十年后的爆发埋好了引线。

## 第三步：词嵌入爆发（2013，word2vec）

2013 年，米科洛夫（Mikolov）等人在 Google 提出 **word2vec（Word to Vector，词转向量）**——专门训练"给每个词一个数字坐标"的算法。如果说 NNLM 的词向量是"买一送一的赠品"，word2vec 就是"专门为生产词向量而生的工厂"。

它的核心思想只有一句话，你已经见过的：**"一个词的意思 = 它身边的伙伴。"** 如果"猫"和"狗"总出现在相似的句子里（都是宠物、都吃粮、都毛茸茸），就让它们的向量靠得近一点。

**word2vec 具体怎么练？两种办法，互为镜像：**

- **CBOW（Continuous Bag-of-Words，连续词袋）**：把被抠掉的中间词补上。给你"我喜欢 _ 狗"，让模型猜中间该是"猫"。像完形填空——你可能已经认出，这和后面 BERT 的预训练是同一招的祖师爷。
- **Skip-gram（跳字模型）**：反过来，给你"喜欢"，让模型猜它周围会出现哪些词（"我""猫"……）。像从一个词联想它的上下文。

不管哪种，套路都一样：**先给每个词随机初始化一个向量，然后反复"猜词—猜错—调向量"，几百万次之后，出现在相似上下文里的词，向量就被越挤越近。** 这又是一次"猜—错—调"（《神经网络基础》的循环），只不过这次被调整的旋钮，是每个词的坐标。

靠这个朴素的规则，词向量学会了神奇的性质：

> 国王 − 男人 + 女人 = 王后

把"国王"的向量减去"男人"的、加上"女人"的，得到的新向量，离它最近的真就是"王后"。**它为什么成立？因为词向量学的不仅是"谁和谁近"，还学会了词之间的"方向"。** "男人→女人"这个方向（性别变换）和"国王→王后"是平行的——向量的加减，捕捉的就是这种关系：国王（男性统治者）− 男性 + 女性 ≈ 女性统治者。**机器第一次"摸到"了词的意思**——意思不再是词典定义，而是向量之间的几何关系。

回扣《神经网络基础》：**词向量就是每个词的"初始特征值"**，后面所有语言模型的输入都是它。但 word2vec 有个硬伤：**一个词只有一个固定的向量**，不管在什么语境里——"苹果"在水果语境和手机语境里，用的是同一个向量，这叫"静态词嵌入"（Static Embedding）。它读不懂"这个词在这里是这个意思"，多义词尤其吃亏。**这个问题的解法，要等到第七步的 Transformer——到时候每个词都会根据当前语境现算一个向量。** 这里先埋个钩子。

## 第四步：RNN / LSTM：机器开始"记忆"（2014—2017）

n-gram 只看前几个词，word2vec 也不管顺序。要让机器像人一样"读完整句话再判断"，怎么办？答案是**让网络"循环"起来**。

**RNN（Recurrent Neural Network，循环神经网络）**的核心设计：一个会"记住"的网络。它一个词一个词地读，每读一个词，就更新一个"内部状态"——相当于"到目前为止这句话讲了什么"的浓缩记忆——然后把这个状态连同下一个词一起处理。就像你读一句话，一边读一边在心里更新"到这儿为止讲的是什么"。

RNN 让机器第一次能"读完整句"，但它有两个致命死穴：

- **串行**：必须一个词一个词地读，没法并行，训练慢。
- **梯度消失**（回收《ReLU激活函数》那篇）：记忆要跨很多个词传递，而反向传播每跨一步都要乘一个小于 1 的数，传几个词，前面词的记忆就"梯度消失"了。所以 RNN 看着读完全句，其实**只记得最近的几个词**。

1997 年发明的 **LSTM（Long Short-Term Memory，长短期记忆网络）**，就是来治"记不住"这个病的：它给 RNN 装了"记忆门"，能决定"这个信息该记住、该更新、还是该忘掉"，靠门控让记忆传得更远。它在 2014 年前后成为 NLP 的主力。

但 LSTM 也只是"记得更远"，串行和记忆有限的硬伤还在。**Transformer 就是来同时治这两个病的。**

## 第五步：注意力登场（2015）

2015 年，机器翻译界引入了**注意力机制（Attention）**——它的直觉，你在《自然语言处理》那篇已经见过：翻译到某个词时，不是只依赖最后那一点记忆，而是**回头"重点看"源句子里最相关的几个词**。就像在嘈杂会场里，你的耳朵会专门锁定同桌的声音，而不是平均听所有人。

注意力的意义是革命性的：**距离第一次不再是问题。** 句子里的"它"，可以直接和 50 个词前的"猫"建立连接，不需要经过中间层层衰减的记忆——连接是"直拨电话"，不是"传话游戏"。

这给所有人一个暗示：也许循环根本不需要。**把注意力发挥到极致，就是下一步。**

## 第六步：Transformer：语言的大一统（2017）⭐ 全文最重

2017 年，谷歌发表论文《Attention Is All You Need》——"你只需要注意力"。标题就是宣言：**去掉循环，全靠注意力。** 这个架构叫 **Transformer（变换器）**。

### 自注意力：每个词重新理解自己

Transformer 的核心机关是**自注意力（Self-Attention）**。它的想法是：**让每个词，自己决定该重点看句子里的哪些其他词，然后据此更新自己的含义。**

每个词会生成三个向量，各司其职：

- **Q（Query，查询）**：我在找什么？
- **K（Key，键）**：我是什么、我能提供什么？
- **V（Value，值）**：我的实际内容是什么？

然后两两配对：每个词的 Q 去"问"所有词的 K，匹配度高的，就分到大的注意力权重——**这个"匹配"算的，正是你在 CNN 里见过的"模板和像素逐格相乘求和"那一套，只是换成了"向量点积"**。最后按权重把各词的 V 加权求和，得到这个词的"新含义"。

类比：会场里，你（Q）喊了一声"谁在讲猫？"，每个人举起牌子（K，我讲什么），你按牌子匹配度，决定集中听谁的内容（V）。**每个词的新含义 = 它认为最重要的那些词的内容，按重要程度混合。**

### 它凭什么碾压 RNN

**并行。** RNN 必须一个词一个词串行读；而 Transformer 里，**每个词都可以同时和所有词算注意力**——整句话一次性处理完，词与词之间没有先后依赖。训练速度因此快了几个数量级，模型才能堆到前所未有的规模。这是 Transformer 胜过 RNN 的根本原因。

### 三个配套部件

- **多头注意力（Multi-Head Attention）**：不只用一组 Q/K/V，而是放好几组并行算，每组"关注"不同方面的关系（一组盯代词指代、一组盯语法、一组盯语义），最后拼起来。像好几个不同角度的分析师同时看同一句话。
- **位置编码（Positional Encoding）**：注意力天生不区分顺序——"猫咬狗"和"狗咬猫"对它来说完全一样。所以每个位置要注入一个"位置标记"，让模型知道词在句子里的先后。
- **残差连接**：你读过的"高速公路"（ResNet 那篇的老朋友）——让梯度能直通，深层不崩。

**回扣《神经网络基础》**：Transformer 依然是"一堆旋钮 + 猜错调参"，只是把原来平平的"线性层"换成了"注意力层"。它的训练方式，就是《机器学习》第五步说的"完形填空"——抠掉一个词让它猜，猜错了反向传播调参。

一个架构统一了翻译、生成、理解、问答——**语言类任务从此不再需要每个任务一套系统。** 2022 年后你看到的所有大模型，没有一个逃得出 Transformer 的掌心。

## 第七步：预训练 + 微调（2018，BERT 和 GPT）

Transformer 结构有了，但还有个大问题：**以前是"每个任务单独训练一个模型"**——翻译一个、问答一个、情感分析一个，又贵又重复。能不能让模型先学会"语言本身"，再学具体任务？

于是 2018 年，**预训练 + 微调（Pretraining + Fine-tuning）**范式横空出世：**先让模型读遍全网文本，学会"语言"（这叫预训练，不需要任何人工标注）；再在具体任务上用少量数据小成本调整（这叫微调）。**

这年出现了两个方向，来自两个思路：

- **BERT（Bidirectional Encoder Representations from Transformers）**：谷歌出品，**双向**理解。预训练方式：**完形填空**——把一句话里的词抠掉一个，让模型猜。它擅长"理解"。
- **GPT（Generative Pre-trained Transformer）**：OpenAI 出品，**单向**生成。预训练方式：**预测下一个词**——给它前半句话，让它猜下一个词。它擅长"生成"。

后来的历史证明，**"预测下一个词"这条路走得更远**——因为"下一个词"这个目标在互联网上无穷无尽（任何一段文本都是教材），模型能无限地自学。

回扣你读过的《机器学习》第五节：这就是**自监督学习**——标准答案藏在原文里，不需要人标注，互联网就是无限的教材。

## 第八步：规模的力量（2020，GPT-3）

范式对了，剩下的就是"喂大"。GPT 家族一年比一年大：GPT-1（2018）1 亿参数 → GPT-2（2019）15 亿 → GPT-3（2020）**1750 亿参数**，训练数据几乎是整个互联网的文本。

这里诞生了最重要的发现：**缩放定律（Scaling Laws）**——模型越大、数据越多、算力越足，能力就平滑地变强，**几乎看不到天花板**。这是"规模"第一次被证明是一条可靠的进步之路。

而且，模型大到某个程度，还会发生一件神秘的事：**涌现（Emergence）**——它突然学会了一些小模型完全不会的技能（算算术、翻译、写代码）。没人设计过这些能力，是规模自己"长"出来的——这是《人工智能》旁注第 1 问"涌现"在语言领域的最好例证。

回扣《ImageNet与GPU》：GPT-3 就是"算法 + 数据 + 算力"三件套在语言领域的重演——Transformer 是算法，互联网是数据，GPU 集群是算力。你读过的那两块燃料，在这儿又烧起来了。

**但 GPT-3 有个尴尬：它只会"续写"，不会"对话"。** 你问它"1+1=？"，它不会停下来回答你，而是把问题当成"上文"，自顾自往下编故事。它缺的是最后一步。

## 第九步：对齐——从"会续写"到"会聊天"（2022）

要让一个"续写机器"变成"会聊天的助手"，需要**对齐（Alignment）**——让模型的行为符合人类的期待。这一步由两块拼成：

- **指令微调（Instruction Tuning）**：用大量"提问—回答"的样本再训练模型，让它学会"被问了就要答，而不是接着编"。
- **RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**：这是《强化学习》那篇的实战。做法：让人给模型的回答打分排序，训练出一个"人类口味预测器"，再用强化学习让模型生成"口味分更高"的回答。

2022 年底，OpenAI 把预训练 + 指令微调 + RLHF 三者合体，ChatGPT 横空出世——两个月月活破亿，全世界第一次被一个"会说话的机器"点燃。**《强化学习》那篇说"从训猫的心理学实验到人类的对话框"，RLHF 就是那条路的终点。**

## 现在的大模型：一次调用，从输入到输出发生了什么

演化史讲完了。但你可能还有一个更"当下"的疑问：**我现在跟 ChatGPT 说一句话，从敲下回车到它吐完最后一个字，内部到底发生了什么？** 这一节把这条流水线完整走一遍。放心——全是老朋友，都是你前几步学过的零件，只是串成了一条线。我们分五站看。

```
你输入 → ①分词 → ②向量化 → ③穿过N层Transformer
       → ④预测下一个词 → ⑤采样 → ⑥追加回去，循环……
       → 直到吐完，显示给你
```

### 第一站：输入怎么进来——分词 + 向量化

你敲下"给我讲个笑话"。模型不认识这句话——它连"句子"是什么都不知道。它要先做两件事：

**① 分词（Tokenization）**：把文本切成一块一块的 **token**（模型的基本单位，一个 token 可能是一个词、半个词、一个标点）。"给我讲个笑话"会被切成几个 token。切完，一句话变成一串 token。

**② 向量化**：每个 token 查"词向量表"，变成一串数字向量（回收 Transformer 第 1 步、第 11 步：真实模型是几千维）。再加上位置编码（Transformer 第 9 步的老朋友），让模型知道谁先谁后。可能还会加一个特殊的"开始标记"。**到这步，你的话变成了一排数字向量，准备进场。**

### 第二站：核心——穿过多层 Transformer

这排向量，现在开始**穿过多层 Transformer 块**（回收 Transformer 第 10 步：多头注意力→残差→归一化→前馈，叠几十上百层）。

每一层都在做同一件事：**让每个 token 看看"它前面"的所有 token，按关系重要性更新自己**（回收 Transformer 批注第 1 条）。注意"前面"这个词——因为大模型是解码器（第 10 步讲过），内部有个掩码，**每个位置只能看它前面的 token，不能偷看后面**。所以"笑话"这个 token 能吸收"给我讲个"的信息，但"给我"看不到"笑话"。

穿完全部层之后，**整句话的上下文信息，都汇聚到了最后一个 token 的位置上**——它现在"融会贯通"了你的整句要求。

### 第三站：预测下一个词——翻词表

最后一个 token 的向量，要变成"下一个词是什么"。它经过一个**词表映射层**：把向量（几千维）映射到"词表大小"的分数（词表通常几万个词，每个词一个分数），再用 softmax（Transformer 第 7 步的老朋友）变成概率——**每一个词各得一个"它是下一个词"的概率**。模型从概率最高的几个候选里，选出下一个词。比如它算出"笑话"概率 0.4、"段子"0.3、"故事"0.15……

### 第四站：采样——不能总选最可能的

这里有个巧妙的机关：**不能每次都选概率最高的那个词**。如果总选最高的，模型会变得机械、爱重复（每句都差不多）。所以它按概率**随机采样**——概率高的更常被选中，但偶尔也会抽到"冷门"的。这个"随机性有多大"，由 **temperature** 控制（你在《大模型应用》里见过的字段）：调低→稳定机械，调高→天马行空。于是它吐出第一个词："从前"。

### 第五站：循环——一个词一个词地"长"出来

**关键真相：模型没有记忆。** 它吐出"从前"之后，不是"接着往下想"，而是把"给我讲个笑话 从前"**拼成新的一整句，从头再跑一遍**——重新分词、向量化、穿过所有层、预测下一个词……如此循环：

```
"给我讲个笑话"          → 预测出"从前"
"给我讲个笑话 从前"      → 预测出"有"
"给我讲个笑话 从前有"    → 预测出"一座"
……每吐一个词，整句重跑一遍
```

循环几百上千次，直到模型吐出"终止标记"或达到长度上限——你才看到一段完整的回答。**你看到的流畅回答，其实是几百次"预测下一个词"循环的结果，一次一个词。**

这也解释了《大模型应用》那篇说过的两个现象：**为什么长对话又慢又贵**（每生成一个词都要从头重算整句历史，上下文越长越贵）；**为什么它看起来"记得"你们聊过什么**（其实每次都是把全部历史原封不动重发）。推理时有个叫"KV 缓存"的技巧能偷懒（把前面算过的中间结果缓存复用，不用每次全算）——那是我们后面要爬的一片叶子，先记着这个名字。

  > **批注 · 第 1 条（读至"第五站：循环"处）— 我的理解**
  >
  > 是的，逻辑上每生成一个 token，模型都要"再处理一遍全部上下文"——因为我们每次把全部历史发给它，而它没有记忆。但真实工程里有 KV 缓存这个优化：前面 token 算过的中间结果（K 和 V）被缓存下来，生成新 token 时只算新 token 自己的部分，再拿它去查所有缓存的旧结果——相当于"接着上次续算"而不是"从头重读"，这才让长对话没慢到不可用。这也正好对应《推理工程》那篇讲的 KV 缓存。

### 回到原点

现在你把这条流水线和演化史连起来看，会发现惊人的一致：**大模型跑一次调用，做的还是它祖宗（n-gram）做的事——预测下一个词。** 只是 n-gram 靠数数、算力弱、记不住远；今天的模型靠 Transformer、几千亿旋钮、记住全网——**目标一样，武器换了七十年的级。** 你从演化史走到这里，正好把"历史"和"现在"接上了。

## 收尾：它的能力与边界

九步走完，你手里有了一张完整的演化地图：

```
数数（n-gram）→ 网络学词（NNLM）→ 词嵌入（word2vec）→ 记忆（RNN/LSTM）
→ 注意力（Attention）→ 大一统（Transformer）→ 预训练（BERT/GPT）
→ 规模（GPT-3）→ 对齐（ChatGPT）
```

每一环都在解决上一环的死穴：n-gram 记不住 → RNN 记住了但串行 → Transformer 并行且全连接 → 规模涌现能力 → 对齐变成助手。**LLM 不是发明，是一连串"补上一个洞"的结果。**

能力不用多说了——生成、翻译、总结、写代码，你天天在用。边界也早就画过（《人工智能》边界节）：**幻觉**（它学的是"哪个词后面该接哪个词"，不是"什么是真的"，所以会一本正经地编）；**没有世界模型**（它从没摔过杯子，所以不懂杯子会碎）。这些边界，正是下一片叶子的土壤。

**总结判断**：大语言模型的全部秘密，可以压缩成一句话——**把"预测下一个词"这件事，用足够大的 Transformer、足够多的数据、足够强的算力，再加上最后的人类对齐。** 听着简单，但它走了一条七十年的路才到今天。
