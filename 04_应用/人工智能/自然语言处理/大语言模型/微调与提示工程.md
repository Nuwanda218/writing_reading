买回一辆车，你得调座椅、设空调；拿到一个基础大模型，你也得调教——但调教它不是改代码，而是两条路线：**改参数（微调）** 和 **改输入（提示工程）**。这篇文章讲清两条路各是什么、各适合什么，以及怎么选。

## 一、先说清：基础模型是什么

你从 OpenAI 之类拿到的"通用模型"，是预训练 + 对齐之后的产品（《GPT 的诞生》那条流水线）。它什么都懂一点，但**不专精**——它懂法律但不会写规范的起诉状，懂代码但不懂你公司内部的项目规范。要让它成为某个领域的"专家"，你有两条路：

- **改参数（微调）**：动模型本身——拿它的"旋钮"继续拧，让它记住你的领域。
- **改输入（提示工程）**：不动模型——每次使用都通过精心设计的"话术"引导它。

一句话：**微调改"脑子"，提示改"题目"。**

## 二、路线一：微调（Fine-tuning）——改脑子

**微调（Fine-tuning）** 的思路：在一个已经训练好的模型上，用**你的领域数据**继续训练一小段，让它的旋钮朝你的方向再拧一点。它在《大语言模型》第七步出现过——预训练学会了语言，微调学具体任务。

**怎么微调？** 基本是《神经网络基础》那套"猜—错—调"循环，只是数据换成你的（比如"1000 条你公司的客服问答"），训练量小得多。两条路：

- **全量微调（Full Fine-tuning）**：所有旋钮都接着拧。效果好，但贵——等于把整个模型再训练一遍。
- **LoRA（Low-Rank Adaptation，低秩适配）**：**只训练一小部分新旋钮**。原理一句话：不动原来的大模型（冻结），在旁边加一个很小的"旋钮模块"（可能只有原模型的 0.1%），只训这个小模块。效果接近全量微调，成本却低了几个数量级——**这是现在微调的默认做法**。想想它像什么：给一个已经会写字的专家，加一副"你的笔迹"小手套，而不是让他重新学写字。

**什么时候该微调？** 三个信号：

1. **你的领域很特殊**：医学术语、法律条文、公司内部黑话，通用模型不会。
2. **你要固定的输出格式**：必须按你的 JSON 结构、必须带你的格式，提示工程管不住。
3. **你要私有化**：模型要部署在你自己机器上，不能每次联网问通用模型（还省钱、合规）。

微调的代价：你需要**自己的数据**（几百到几千条高质量样本），以及训练成本（虽然 LoRA 已经便宜很多）。

## 三、路线二：提示工程（Prompt Engineering）——改题目

**提示工程（Prompt Engineering）** 的思路：模型不动，用**话术**引导它。你发的每句话都是"提示"（Prompt），提示写得好，通用模型也能顶半个专家。几样核心武器：

**武器一：few-shot（少样本示例）。** 在问题前放几个"例子"，让模型照着学（《LLM 的能力与边界》里讲过的上下文学习）：

```
翻译成英文：
你好 → Hello
谢谢 → Thank you
再见 →
```

模型看到两个例子，第三个就知道该翻成 "Goodbye"——**不改参数，纯靠例子示范。**

**武器二：CoT（Chain of Thought，思维链）。** 让模型"把思路写出来再给答案"，而不是直接蹦结论。研究反复证明：**你逼它一步步推理，它推理得更准**。两种做法——提示里写"请一步步思考"，或者直接给一个"带思考过程"的示例。现在主流大模型默认就会内部思考，但显式要求仍有奇效。

**武器三：system prompt（系统提示）**——你在《大模型应用》里见过的那个"导演"。它在对话最开头，规定角色、风格、约束：

```
你是一个严谨的中文法律助手。只依据用户提供的事实回答；
不确定就说不确定；回答不超过 200 字。
```

**武器四：结构化指令**：明确输出格式（"用 JSON 返回"）、明确步骤、明确负面清单（"不要提无关内容"）。**提示工程的核心心法只有一句：把模型当成一个能力很强但必须把要求说清楚的新员工**——它不会读心，你指令越具体，它执行越准。

**什么时候该用提示？** 大部分时候！因为：

1. **零成本**：不用训练，立刻生效。
2. **灵活**：换句话就换种行为，随时改。
3. **无需数据**：微调要准备样本，提示不用。

## 四、怎么选：一张决策图

微调和提示不是二选一，而是**先用提示、不够再微调**：

```
你的任务，通用模型加提示能做好吗？
　├─ 能 → 用提示工程（零成本、灵活）
　└─ 不能（领域特殊 / 格式固定 / 要私有部署）
　　　→ 微调（LoRA 为主），并且：微调之后依然搭配提示用
```

实际工程里，**提示是默认，微调是特例**——而且微调后的模型，你仍然要用提示工程去调用它。两者是叠加关系，不是竞争关系。行业里最常见的组合是：**基础模型 + LoRA 微调（掌握你的领域）+ 精心设计的 system prompt（规定每次怎么干活）+ few-shot（给示范）**。

（补充一个概念：**RAG（Retrieval-Augmented Generation，检索增强生成）**——它其实是一条"伪微调"路线：不改模型，但每次提问前先**去你的知识库检索相关段落**，把结果塞进提示里再让模型回答。它让模型"用上"你私有的大量资料，又不花训练成本。微调"记住"，RAG"查阅"——两个是互补的。）

  > **批注 · 第 1 条（读至"补充：RAG"处）— 我的理解**
  >
  > 用 LLM 做特定知识的问答和检索确实是它的甜区：因为通过 RAG 把确定性的参考资料塞进上下文后，模型从"凭词序概率编造"变成了"照着资料转述"——幻觉的根源（脑子里没有事实库）被绕开了，它成了把资料讲成流畅人话的"讲解员"。自然语言加持让答案比一堆链接好读得多。但要诚实：转述仍可能曲解或遗漏，准确性取决于检索能否找到对的资料、资料本身对不对。

**总结判断**：调教大模型的两条路，本质是一个古老问题的两种解法——**"让工具适配任务"（微调）还是"让任务适配工具"（提示）**。提示工程零成本但浅，微调贵但深。聪明的用法永远是：**先用提示撬动 80% 的需求，剩下 20% 的硬骨头交给 LoRA。** 别忘了《神经网络基础》的初心——模型是一堆旋钮，提示是"不动旋钮换用法"，微调是"把旋钮再拧一截"。
