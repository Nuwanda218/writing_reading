# 智能体 Agent：让大模型长出"手"和"腿"

> 变更日志：
> - v1.0 | 2026-08-22 10:39:56 | 初版：大模型 + 工具 + 记忆 + 规划——从"会说话"到"会干活"

到目前为止，你学的都是大模型"会说话"。但你大概也注意到了一个大大的反差：**它明明能写代码，却不能帮你把代码跑起来；明明能查资料，却不能真的上网帮你买东西。** 智能体（Agent）要解决的，就是这个反差——**让大模型从"只动嘴"变成"动手干活"**。这篇文章讲智能体是什么、由什么组成、怎么运作。

## 一、它是什么：一句话定义

**智能体（Agent）= 大模型 + 工具 + 记忆 + 规划。**

普通对话里，大模型只有一张嘴——你问它答，它什么都不能碰。智能体给它装上"手"（工具）、"记忆"（记住你之前的偏好）、"脑子"（自己规划步骤），让它能**主动完成一整件事**，而不只是回答一句话。

对比一下就清楚：

| | 普通对话 | 智能体 |
|---|---|---|
| 你的输入 | "帮我订下周去上海的机票" | 同一句话 |
| 模型行为 | 给你一篇"如何订机票"的攻略 | 真的去查航班、比价、下单 |
| 本质 | 说话 | 干活 |

**一句话：普通大模型是"顾问"，智能体是"员工"。** 你雇员工干活，员工需要工具、需要记住上下文、需要自己拆解任务——智能体就是把这套"员工能力"装进大模型。

## 二、核心组件一：工具调用（它会"用工具"了）

这是智能体的地基，也是你唯一已经见过的东西——**《大模型应用》第五节讲过的 tools 字段**。回顾一下那个关键机制：

**模型并不会真的执行工具，它只负责"决定调哪个工具、传什么参数"，真正的执行由你的程序完成。** 完整回合是这样的：

```
① 你：帮我查北京明天的天气
② 模型：我建议调用 get_weather(city=北京)   ← 模型只做"决定"
③ 你的程序：真的去调用天气 API，拿到结果
④ 模型：基于结果组织回答——"明天多云，18 度"
```

这个"工具调用（Function Calling）"就是智能体的"手"。工具的种类可以无限扩展：**查天气、算数学（调用计算器）、搜网页、执行代码、发邮件、操作数据库……** 每给模型配一个工具，它就多一只手。这就是《大模型应用》里说的"语言模型长出'手'"。

## 三、核心组件二：记忆（它记得住"上下文"了）

普通大模型没有记忆（每次全量重发，你学过）。智能体要干活，必须记得住，所以给它装两层记忆：

- **短期记忆**：当前任务的上下文。比如你让它"先查航班，再订酒店"，它得记得前一步的结果。这其实就是对话历史（靠上下文窗口装）。
- **长期记忆**：跨任务的持久信息。比如"用户习惯坐靠窗、偏好经济舱、讨厌红眼航班"。存哪里？——存进外部数据库（向量数据库），需要时检索出来塞回上下文。这是 RAG（《微调与提示工程》提过）在智能体里的应用：**把"记得什么"从模型的脑内，搬到脑外的存储里。**

有了记忆，智能体才不是"每次失忆的员工"。

## 四、核心组件三：规划（它会拆解任务）

工具和记忆是"零件"，把它们组织起来的，是**规划（Planning）**——让模型自己把大任务拆成小步骤。这是智能体的"脑子"。

一个常见的规划框架叫 **ReAct（Reasoning + Acting，推理 + 行动）**，它的循环极像人做事：

```
思考（Think）→ 行动（Act）→ 观察（Observe）→ 再思考……
```

完整走一遍"帮我订下周去上海的机票"：

```
① 思考：订机票需要先知道日期、航班、价格 → 我可以先查航班
② 行动：调用 search_flights(上海, 下周三)   ← 用工具
③ 观察：看到航班列表 [CA1234 ¥800, MU5678 ¥950, …]
④ 思考：价格最低的是 CA1234，我可以推荐它，或直接订
⑤ 行动：调用 book_flight(CA1234)
⑥ 观察：订票成功，订单号 XXX
⑦ 思考：完成了，可以汇报了
→ 回答：已为你订好 CA1234，价格 800 元
```

看清楚这个循环：**模型每走一步都在"思考 → 动手 → 看结果 → 再想"**——这正是《搜索与推理》那篇里"搜索"思想的现代版，只是"搜索的每一步"变成了"调用一次工具"。**智能体 = 搜索 + 工具 + 语言理解的三合一。**

## 五、进阶：多智能体协作

一个智能体不够，还能让**一群智能体分工**。比如写一篇报告，可以拆成：一个负责查资料、一个负责写初稿、一个负责校对——**它们通过"对话"互相传递结果**。每个智能体有自己独立的 system prompt 和工具，像一个团队各司其职。这种"多智能体（Multi-Agent）"架构，是 2025 年以来企业级 AI 应用的热门方向。

## 六、现状、风险与挑战

智能体现在已经能干什么？——**写代码并运行调试（编程助手 Agent）、查资料写报告、处理邮件、操作浏览器和软件（computer use，像人一样点屏幕）**。它们离"全自动替你干活"还很远，但已经在很多"半自动"场景落地。

三座大山，也是你要保持清醒的地方：

1. **不可靠**：模型可能选错工具、传错参数、中途跑偏。智能体链条越长，出错概率越高——"一步错步步错"。**目前工业界对智能体的态度是"人机协同"：让人监督关键步骤，而不是全放权。**
2. **幻觉放大了**：普通对话里幻觉只是"答错了"；智能体里幻觉可能变成"执行了错误的操作"——**错误从"文字"变成了"行动"，代价大得多。**
3. **安全和权限**：给智能体的工具权限越大，风险越大。必须做权限控制（什么能调、什么不能调）、操作审计（记录它每一步干了什么）。

**总结判断**：智能体是大模型的"最后一公里"——**从"会说话"到"会干活"，装上了工具（手）、记忆（脑外存储）、规划（思考循环）**。它不是什么新模型，而是把你已经学过的所有零件（大模型、工具调用、RAG、搜索、多模态）组装成一台"能替你做事"的机器。你一路学下来的每一步，到这里都派上了用场——这就是整棵 LLM 树的顶点。
