先问你一个小问题：你凭什么知道"猫 追 老鼠"里，**"猫"是追的那个，不是被追的？** 答案是：靠"猫"和"追"、"追"和"老鼠"之间的关系——"猫"是动作的发出者，"老鼠"是承受者。

Transformer 要解决的，就是让机器也能搞懂这种"词与词的关系"。这篇文章我们一步步来，从"词怎么变成数字"开始，每一步都亲手算给你看。**全程只需要小学算术，但你得跟着一步步走，不许跳。** 每一步结尾都有一个小总结，读通了再走下一步。

## 第 1 步：词怎么变成数字（温故）

机器只认数字。所以在进入 Transformer 之前，每个词必须先变成一串数字——**这就是《大语言模型》第三步讲过的词向量**：每个词一个数字列表，意思相近的词，数字也相近。

为了能手算，我们用极简的 2 维向量，把"猫 追 老鼠"变成三串数字：

```
猫   = [1, 0]
追   = [0, 1]
老鼠 = [1, 1]
```

**小总结**：机器眼里没有"猫"这个字，只有 `[1, 0]` 这一串数字。

## 第 2 步：光有数字还不够——词得知道"自己跟谁关系近"

现在机器知道"猫"是 `[1, 0]`，但它仍然不知道"猫"是"追"的主语。为什么？因为 `[1, 0]` 只是"猫"的**词典义**（它是猫），没包含它在这个句子里的**角色**（它是追的动作发出者）。

我们的目标：让"猫"的新数字，把"追"和"老鼠"的信息也吸收进来——变成"追着老鼠跑的那只猫"。

怎么做到？需要一个机制：**让每个词"看看句子里的别的词，按关系重要性，从别人那里拿一点信息过来。** 这就是**自注意力（Self-Attention）**的终极目标。接下来所有步骤，都是在给这个机制搭零件。

**小总结**：自注意力 = 每个词从"别的词"那里按重要性吸收信息，更新自己的含义。

## 第 3 步：怎么衡量"两个词关系近不近"？——引出 Q 和 K

要让"猫"决定"该从谁那里拿多少"，第一步是：**怎么用数字衡量"猫"和"追"关系近，和"老鼠"关系也不远？**

想想你在食堂打饭的场景。你饿了，想吃米饭。你走进食堂，心里揣着一个念头："**我要找米饭**"——这是你发出的需求。每个窗口前挂着一块牌子，写着"米饭""面条""盖浇饭"——这是每个窗口**声称自己是什么**。你的需求，和哪个窗口的牌子对得上，你就知道该去哪个窗口。

- 你的"**我要找什么**" → 叫 **Q（Query，查询）**
- 每个窗口的"**我是什么**" → 叫 **K（Key，键）**

**两个东西关系近不近 = Q 和 K 对得上不对得上。** 你的 Q 是"米饭"，窗口的 K 是"米饭"，对上了——关系近；窗口的 K 是"面条"，对不上——关系远。

所以，每个词为了参加这场"对话"，都要准备两样东西：

- **Q（Query，查询）**：我在找什么？——我主动发出的问题。
- **K（Key，键）**：我是什么？——我举着的牌子，供别人来匹配。

**小总结**：关系近不近，用"我的 Q 和你的 K 对得上吗"来衡量。Q = 我在找什么，K = 我是什么。

## 第 4 步：怎么用数字算"对得上不对得上"？——点积

有了 Q 和 K，怎么用数字判断"对得上"？用**点积（Dot Product）**：把两个向量的对应位置相乘，再全部加起来。

```
向量 A = [a₁, a₂]，向量 B = [b₁, b₂]
点积 = a₁×b₁ + a₂×b₂
```

举个例子，猫 的 Q = [0.5, 0.8]，和 追 的 K = [0.2, 0.7] 做点积：

```
0.5×0.2 + 0.8×0.7 = 0.10 + 0.56 = 0.66
```

**为什么点积大 = 关系近？** 直觉是这样：两个向量如果"方向一致"——第一个数都偏正、第二个数都偏正——那么对应相乘都是正数，加起来自然大；如果方向相反，正的乘负的，互相抵消，加起来就小。**点积量的是"这两个向量有多合拍"。** 你只需要记住：点积 = 一把量"合不合得来"的尺子，数值越大越合拍。

**小总结**：点积 = 两个向量对应相乘再求和，数值越大 = 越合拍。

## 第 5 步：Q/K/V 三样齐了——V 是"实际内容"

食堂的例子还差最后一样东西。假设两个窗口的牌子都写着"米饭"（K 一样），但你走近一看——一个窗口的饭很好吃，一个窗口的饭很难吃。**牌子（K）只能说明"我声称是什么"，不代表"我真的能给你什么"。**

所以每个词还要准备第三样：

- **V（Value，值）**：我的实际内容是什么？——别人真要采纳我时，从我这儿拿走的东西。

**三样齐全，各司其职**：
- **Q（Query）**：我在找什么？（我发出的问题）
- **K（Key）**：我是什么？（我举的牌子）
- **V（Value）**：我的内容是什么？（别人真拿走的东西）

**Q/K/V 这三个向量从哪来？不是天降的，是算出来的。** 每个词的原始向量（第 1 步那个 `[1, 0]`），分别乘三个矩阵 W_Q、W_K、W_V 得到——**矩阵就是《神经网络基础》里的"旋钮"，训练时学出来的**。演示一个：假设猫 = [1, 0]，W_Q = [[0.5, 0.3], [0.1, 0.4]]：

```
猫的 Q = [1, 0] × W_Q = [1×0.5 + 0×0.1,  1×0.3 + 0×0.4] = [0.5, 0.3]
```

看到了吗？就是"乘一下、加一下"——和 CNN 里卷积核扫图的运算一模一样，只是这次矩阵是训练出来的。为了专心看注意力流程，下面我们直接给"算好的"三张表（现实中是乘 W 矩阵得来的）：

```
词      Q          K          V
猫     [0.5, 0.8]  [0.3, 0.1]  [1, 0]
追     [0.7, 0.2]  [0.2, 0.7]  [0, 1]
老鼠   [0.1, 0.9]  [0.1, 0.2]  [1, 1]
```

**小总结**：每个词都有三样——Q（找什么）、K（是什么）、V（给什么）。它们都是原始向量乘旋钮矩阵算出来的。

## 第 6 步：让"猫"重新理解自己——打分

现在开始真正干活。我们让"猫"重新理解自己，分三步：**先打分，再分比例，最后混合。**

**第一步：打分。** 猫 的 Q 是 [0.5, 0.8]——"我在找什么"。它把这个 Q 拿去和全句每个词的 K 做点积（第 4 步的尺子），看"和谁合得来"：

```
Q(猫) · K(猫)   = 0.5×0.3 + 0.8×0.1 = 0.15 + 0.08 = 0.23   ← 猫 和自己
Q(猫) · K(追)   = 0.5×0.2 + 0.8×0.7 = 0.10 + 0.56 = 0.66   ← 猫 vs 追
Q(猫) · K(老鼠) = 0.5×0.1 + 0.8×0.2 = 0.05 + 0.16 = 0.21   ← 猫 vs 老鼠
```

分数越高 = 关系越紧。这里"猫"和"追"的 0.66 最高——**模型正在学习"猫"和"追"关系紧密**（这是它从数据里学出来的，不是我们指定的）。这三个数，就是"猫"对全句每个词的**注意力原始分数**。

**小总结**：用"猫"的 Q 点积每个词的 K，得到"猫"和谁关系紧的分数。

## 第 7 步：softmax——把分数变成"占比"

分数 [0.23, 0.66, 0.21] 还不能直接用，因为它有两个毛病：不是正数（可能为负）、加起来不等于 1。而我们下一步要做"按比例混合"，需要**权重加起来刚好等于 1**。

于是引入 **Softmax（归一化指数函数）**：把任意一串数，变成"和为 1 的比例"。它做两件事：①任何数都变成正数；②按原大小分比例——分高的占比大、分低的占比小。

我们的分数 [0.23, 0.66, 0.21] 经过 softmax，得到（示意值，不用算公式）：

```
注意力权重：
  猫     → 0.28
  追     → 0.48   ← 占比最大，因为它和"猫"分数最高
  老鼠   → 0.24
  合计   → 1.00
```

**"猫"把自己近一半的注意力分给了"追"**——这就像一个分蛋糕仪式：谁对"猫"更重要，谁就分到更大的一块。

**小总结**：softmax 把分数变成"加起来等于 1 的比例"——注意力权重。

## 第 8 步：加权求和——混合出"新猫"

最后一步：**把每个词的 V（实际内容），按注意力权重加权求和**。V 是"内容"，加权求和 = 按重要程度混合。

```
猫 的新含义 = 0.28×V(猫) + 0.48×V(追) + 0.24×V(老鼠)
           = 0.28×[1, 0] + 0.48×[0, 1] + 0.24×[1, 1]
           = [0.28 + 0.24,  0.48 + 0.24]          ← 每个维度分别算
           = [0.52, 0.72]
```

对比一下：猫 原来的向量是 [1, 0]，现在是 [0.52, 0.72]。**它变了——它吸收了"追"和"老鼠"的信息**，不再是孤立的"猫"，而是"追着老鼠的那只猫"。句子里的每个词都同时做同样的事：**打分 → 分比例 → 混合 → 得到新含义。**

到这里，你手上已经握着自注意力的全部流程了：

```
每个词：自己的Q 去问全句所有词的K → 分数 → softmax变权重 → 按权重混合V → 新含义
```

**小总结**：自注意力 = 每个词问所有词 → 打分 → 分比例 → 混合内容 → 得到"和上下文融合后的新自己"。

  > **批注 · 第 1 条（读至"第 8 步：加权求和"处）— 我的理解**
  >
  > Transformer 不是做"预处理"，而是模型每一层都在做核心计算：每一层都让每个 token 和全句所有 token 算关联（打分→混合），token 的新向量因此从"单纯的实体"变成"带着上下文关系的实体"。而且这个流程会重复很多层，一层比一层"更懂关系"。

## 第 9 步：为什么能并行？加上多头和位置

**并行（这是它能碾压 RNN 的根本原因）。** RNN 读词有先后，第 3 个词必须等前两个处理完。而这里，每个词的 Q/K/V 都只来自它自己的向量——**谁也不用等谁**，所有词可以同时算 Q/K/V、同时互相打分、同时混合。整句话一次性处理完。就这一个差别，训练速度快了几个数量级——**没有并行，就没有 GPT-3 的 1750 亿参数。**

**多头注意力（Multi-Head Attention）**。一组 Q/K/V 只能学一种"关系"，可一句话里同时有好几种：代词指代（"它"→"猫"）、语法结构（谁是主语）、语义关联。解法：**放 H 组**（比如 8 组）Q/K/V，每组学一种关系，各算各的注意力，最后拼起来。像 8 个不同角度的分析师同时看同一句话。**一个头看不全，多个头互补。**

**位置编码（Positional Encoding）**。自注意力有个盲点：**它天生不分顺序。** "猫咬狗"和"狗咬猫"，对注意力来说两组的点积一模一样——可意思完全相反！解法：送词进模型前，给每个位置加一个"位置标记"（第 1 位的词 + 位置1的标记，第 3 位的词 + 位置3的标记），让模型知道谁先谁后。

**小总结**：并行让所有词同时算（所以快）；多头让好几组关系同时学；位置编码把"顺序"重新注入。

## 第 10 步：搭完整座楼

自注意力是心脏，但一个能用的"块"还要装三件配套。一个 **Transformer 块（Transformer Block）** 长这样：

```
输入（一句话所有词的向量）
  │
  ▼
多头注意力 ──→ 结果①
  │
  ⊕ 残差连接：输入 + 结果①（"高速公路"，梯度能直通，深层不崩）
  │
  ▼
层归一化：把数字拉回标准范围（防止深层数值越算越乱）
  │
  ▼
前馈网络：一个小的全连接层，给每个词"再想想"（注意力管词与词，它管每个词自己想清）
  │
  ⊕ 残差连接
  │
  ▼
层归一化
  │
  ▼
输出 → 作为下一块的输入
```

- **残差连接（Residual Connection）**：你读过的"高速公路"（《ReLU激活函数》里讲的那个）——把输入直接加到输出上，梯度能一路直通。它让 Transformer 能堆几十上百层。
- **层归一化（Layer Normalization）**：把每个位置的数字"拉正"（均值归 0、波动归 1），防止深层数值漂移。
- **前馈网络（Feed-Forward Network，简称 FFN）**：一个普通全连接层，对每个词单独再加工——**注意力负责"词和词之间"，前馈负责"每个词自己想清楚"。**

把很多这样的块**叠起来**，就是深层 Transformer——每一块都把词的表示往"更接近答案"推进一步。

最后，按"读"还是"写"，Transformer 分两半：
- **编码器（Encoder）**：**双向**读——每个词能同时看前后所有词。适合"理解"（BERT 用这个）。
- **解码器（Decoder）**：**单向**写——每个词只能看它前面的词（因为要预测下一个词，不能偷看答案，内部有"掩码"挡着未来）。适合"生成"。

**大语言模型（GPT 系）走的是解码器**——因为它的核心任务是"预测下一个词"，天然只能看前面。**你天天聊天的 LLM，就是一大堆解码器块叠起来。**

**小总结**：Transformer 块 = 多头注意力 + 残差 + 归一化 + 前馈，叠很多层；LLM 用的是"单向写"的解码器。

## 第 11 步：现实世界的两个数字——token 维度 和 参数量

你可能会问：我们这里用的是 2 维向量、3 个词，现实里的模型真也是这样吗？当然不是——现实里数字大得多，但道理一模一样。有两个数字你以后会反复见到：

**数字一：token 的向量维度。** 现代大模型的 token 向量通常有 **4096 ~ 12288 维**（取决于模型大小）——意思是每个 token 是一串几千上万位的数字。常见例子：BERT-base 是 768 维，GPT-2 是 1600 维，LLaMA-2 7B 是 4096 维，GPT-3 是 12288 维。规律一眼可见：**模型越大，维度越高。**

**数字二：模型参数量。** 参数量 = 模型里所有"旋钮"（可调数字）的总数。回收《神经网络基础》：整个模型是一堆旋钮，参数量就是把它们全部数一遍。它主要由三块构成：每一层的权重矩阵（W_Q/W_K/W_V、前馈网络的权重）、偏置（每个神经元一个额外小数）、嵌入矩阵（词向量表）。一个 4096×4096 的权重矩阵就是 4096×4096 ≈ **1678 万个参数**；几十上百层、每层好几个这样的矩阵，叠起来就是几百亿。GPT-3 = 1750 亿参数（175B），LLaMA-2 70B = 700 亿。**你听到的"7B 模型""70B 模型"，B 就是 Billion（十亿），指的就是参数量。** 参数量为什么总被提起？因为规模直接决定能力（《大语言模型》第八步的缩放定律）——它是"规模"最直观的度量，所以各家模型都爱拿它"秀肌肉"。

**小总结**：我们手算用 2 维、3 个词，是为了看懂原理；现实里是几千维、几千亿参数——道理完全一样，只是放大了上万倍。

## 收尾：它是心脏，但也有软肋

把整篇压缩成一张流程图：

```
词(向量+位置) → 生成 Q/K/V → Q 问所有 K 打分 → softmax 变权重
  → 按权重混合 V → 新含义 → 多头 ×H → 残差+归一化 → 前馈 → 下一块……
```

**它凭什么成为心脏**：并行（堆得起规模）+ 全连接（长距离不衰减）+ 通用（翻译、生成、理解一个架构通吃）。回扣《神经网络基础》最后那句：**Transformer 依然是"一堆旋钮 + 猜错调参"，只是把 CNN 的"卷积"换成了"注意力"**——CNN 用"小窗口 + 共享权重"看图像，Transformer 用"每词看全句 + 共享权重"看语言，哲学同源。

**一个必须知道的软肋**：注意力是**二次方复杂度**——一句话有 n 个词，就要算 n×n 次"词与词的配对"。句子短没事，长到几千词，计算量暴涨。这就是为什么 LLM 的"长上下文"一直是难题，也是各种"稀疏注意力""KV 缓存"技术拼命优化的对象——**你以后读到"上下文长度"的争论，根子就在这。**

**总结判断**：Transformer 的全部机关，一句话记住——**每个词给自己发三张名片（Q 找什么、K 是什么、V 给什么），然后互相打分、按分混合，得到"跟上下文融合后的新自己"；放多组眼睛一起看、加上位置感和残差高速公路，叠成一栋楼。** 它是大模型的心脏，也是你读懂一切 LLM 论文的钥匙。
